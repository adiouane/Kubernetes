GitLab and ArgoCD Workflow

Automating CI/CD with GitLab and ArgoCD

Introduction

This workflow demonstrates how to automate Continuous Integration and Continuous Deployment (CI/CD) using GitLab for source code management and CI, and ArgoCD for GitOps-based CD. The setup is deployed on a Kubernetes cluster using k3d.

GitLab Workflow

GitLab is used for source code management, CI pipelines, and container registry. Below are the key steps:

  • Cluster Setup: A k3d Kubernetes cluster is created with LoadBalancer support.
  • GitLab Installation: GitLab is deployed using Helm with a custom gitlab-values.yaml configuration.
  • Service Exposure: The gitlab-webservice-default service is patched to use LoadBalancer for external access.
  • Access: GitLab is accessible at http://gitlab.localhost:8080.
  • Authentication: The default username is root, and the password is retrieved from the Kubernetes secret.

ArgoCD Workflow

ArgoCD is used for GitOps-based Continuous Deployment. Below are the key steps:

  • Installation: ArgoCD is installed using the official manifest in the argocd namespace.
  • Service Exposure: The argocd-server service is patched to use LoadBalancer for external access.
  • Access: ArgoCD is accessible at https://localhost:8843.
  • Authentication: The default username is admin, and the password is retrieved from the Kubernetes secret.
  • Application Deployment: An ArgoCD application is created to sync the GitLab repository with the Kubernetes cluster.

Workflow Diagram

Below is a high-level diagram of the workflow:

Steps:

  1. Developers push code to GitLab.
  2. GitLab CI pipelines build and test the application.
  3. ArgoCD monitors the GitLab repository for changes.
  4. ArgoCD deploys the application to the Kubernetes cluster.

Conclusion

This setup provides a robust CI/CD pipeline using GitLab for CI and ArgoCD for CD. By leveraging Kubernetes and GitOps, the workflow ensures consistent and automated deployments.
